# Maintenance guide

Repository: `GoGoKo699/Upstream-Electron-Preparation`.

Resolve the live main revision and read [AGENTS](AGENTS.md),
[model and claims](research/MODEL_AND_CLAIMS.md) and the
[current work order](work_orders/CURRENT.md) before changing the repository.
The owner has authorized modifications and merge through a reviewed pull request.

## Reader and source authority

- [README](README.md) introduces the physical question and result.
- [Tutorial guide](tutorial/README.md) and [bridge](tutorial/BRIDGE.md) provide the learning route.
- [Claim map](research/MODEL_AND_CLAIMS.md), [frontier](research/FIDELITY_FRONTIER.md) and [proof audit](research/FRONTIER_AUDIT.md) define the mathematical task and proof.
- [Literature ledger](literature/PRIOR_ART.md) records source attribution and reading depth.
- [Scope and evidence](STATUS.md) and [verification policy](VERIFICATION.md) describe the evidence.
- [Archive](archive/README.md) preserves development history and internal plans.

## Maintenance rules

Keep reader-facing pages organized around results, assumptions, derivations and
reproduction. Put dated decisions and progress records in the archive or PR
handoff. State the model's scope where it defines a claim; avoid repeated lists
of unrelated work or credentials.

Preserve the fixed control class, full-state objective, launched-edge energy,
all protected source/reference copies and warning-bearing history. For an edit,
review the diff, run the checks in [AGENTS](AGENTS.md), and inspect the actual
PR and merged-main artifacts. Record the exact revisions and numerical
differences in the PR handoff. The existing MIT license is retained.
